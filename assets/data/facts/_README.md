# 数値の判断記録（facts/）

機種ごとに1ファイル。**「今この値である理由」**を残す場所。

## なぜ要るか

記録が無いと、自動タスクが走るたびに採用値が変わる（今日は600G、明日は620G…）。
読者から見て一番信用を失うパターンなので、**何をどう決めたかを残す**。

## ★一番大事なルール★

**記録があっても、毎回必ず検索し直す。**
「根拠を書いてあるから検索しない」は禁止。記録はキャッシュではなく**判断の基準**。

正しい順序:

1. 毎回まず検索する
2. 検索結果を、記録してある `sources` と突き合わせる
3. **同じなら** → 値を維持（静かに終わる）
4. **違っていたら** → 出典が更新されたかもしれない。
   黙って上書きせず、`conflicts` に積んで再判断へ回す

## 形

```json
{
  "slug": "gogo_juggler3",
  "name": "ゴーゴージャグラー3",
  "facts": {
    "grape.setting_1": {
      "value": "1/6.25",
      "counting": "通常時の単独ぶどう",
      "decided_on": "2026-07-28",
      "decided_by": "claude+codex",
      "why": "juggler7 が『通常時の単独ぶどう』と明記し当サイト値と一致。DMM(1/6.81)は数え方が別。",
      "sources": [
        {"site": "juggler7", "url": "...", "value": "1/6.25", "counting": "通常時の単独ぶどう"},
        {"site": "DMM", "url": "...", "value": "1/6.81", "counting": "明記なし"}
      ]
    }
  },
  "history": []
}
```

## 決まっていること

- **数え方(`counting`)を値と一緒に持つ**。ぶどう確率はサイトごとに数え方が違い、
  値だけ揃えても読者のカウントと噛み合わない（ゴーゴージャグラー3で実際に発生）。
- 1つの値でも食い違ったら、**その設定だけでなく行全体を止める**。
  設定1〜5はA社・設定6だけB社、というつぎはぎをしない。
- 「2ドメイン一致」は**ドメインの数ではなく情報の独立性**で見る。
  同じ表を転載しているページは2つでも1つと数える。
- `history` は**追記だけ**。過去の判断を上書きしない（いつ何故変わったかが消えるため）。
